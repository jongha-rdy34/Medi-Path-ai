# ADR 0001: LLM 선택 (증상 구조화·추가 질문·설명)

- 상태: **제안** (사용자 결정 대기)
- 날짜: 2026-11-11
- 관련: SPEC 3.1절, `tasks/todo.md` T13·T14, `ml-service/llm/`

## 배경

증상 문장을 표준 증상 ID로 구조화하고, 추가 질문과 쉬운 설명을 만드는 LLM이 필요합니다.
코드는 `LLMProvider` 인터페이스(`extract_symptoms`, `next_questions`, `explain`)에만 의존하므로 모델 교체는 설정(`GEMINI_MODEL`)으로 합니다.
사용자 결정: **Gemini 무료 등급 키**로 평가하고, 필요해지면 OpenAI 유료 키($5)를 대안으로 씁니다.

## 무료 등급 한도

| 모델 | RPM | TPM | RPD |
|---|---|---|---|
| Gemini 3.5 Flash Lite | 15 | 250K | 500 |
| Gemini 3.1 Flash Lite | 15 | 250K | 500 |

출처: Google AI Studio의 Rate limits 화면, 프로젝트 "MediPath"(무료 등급), 2026-11-11 사용자 확인. 한도는 모델별로 따로 잡힙니다.

## 평가 방법

- 평가셋: `ml-service/llm/eval/cases.jsonl` — **가상의 한국어 문장 59개**(실존 인물·개인정보 없음). Kaggle 41종 질환을 모두 포함하고, 구어체 변형과 위험 요인(성 접촉, 가족력 등)을 일부러 언급하는 문장 4개를 넣었습니다.
- 지표: 증상 추출 micro Precision/Recall/F1, JSON 파싱 성공률, 평균·p95 지연, 토큰 사용량.
- 실행: `python -m llm.eval --provider gemini --model <모델>` (호출 간격 4초 이상, 429·503 지수 백오프, 응답 캐시 `llm/eval/.cache/`는 커밋하지 않음). 결과: `ml-service/llm/eval/results/<모델>.json`
- 정답 라벨 정정: 첫 실행 뒤 c038 문장("기침이 몇 주째…")의 정답에서 `cough`가 빠진 라벨 오류를 발견해 고쳤습니다. 아래 수치는 정정 후 재채점 값입니다.
- end-to-end: 같은 결과의 추출 증상을 베이스라인 분류 모델(T14)에 넣어 질환 Top-1·Top-3와 1순위 진료과 일치율을 잽니다(`python -m triage.e2e <결과 파일>`, API 추가 호출 없음).

## 서비스 운영 메모 (기록만, 구현은 W3)

- **대화 1건당 LLM 호출 수(추정)**: 증상 추출 1~2회(첫 메시지 + 추가 질문에 대한 답) + 추가 질문 생성 0~1회 + 설명 1회 = **약 3~4회**.
- **무료 한도로 감당 가능한 사용자 수**: 500 RPD는 모든 사용자가 나눠 쓰는 양입니다. 모델 하나로 **하루 약 125~165건의 대화**입니다. 분당 15회 한도 때문에 동시에 4~5명이 넘으면 대기가 생깁니다.
- **한도를 넘었을 때의 대체 동작(후보)**
  1. 규칙 기반 증상 선택 화면: 증상 사전(`data/mappings/symptoms.csv`)에서 사용자가 직접 고르면 LLM 없이 분류 모델과 위급 신호 규칙만으로 결과를 냅니다.
  2. 한도가 따로 잡히는 두 번째 Flash-Lite 모델로 전환합니다.
  3. 설명문 생성을 템플릿 문장으로 대체해 호출 수를 줄입니다.
- **데이터 원칙**: 무료 등급에서는 입력이 Google 제품 개선에 쓰일 수 있습니다. 평가셋은 가상 문장만 쓰고, 서비스에서도 이름·연락처·정확한 주소 같은 개인 식별 정보를 LLM에 보내지 않습니다(SPEC 6절). 위험 요인 3종은 묻지도 추출하지도 않습니다.

## 기술 메모

- Gemini는 128개 값의 `symptom_id` enum이 든 JSON 스키마를 거절합니다(400 INVALID_ARGUMENT, 100개는 통과, `anyOf` 분할도 거절, 2026-11-11 확인). 그래서 증상 ID는 프롬프트 사전(위험 요인 제외)과 파싱 후 필터(`sanitize_symptoms`)로 강제합니다.
- 일시적 과부하(503)가 실제로 발생했습니다. 429와 함께 지수 백오프로 재시도합니다.
- 분류 모델의 그룹 분할 Top-3 1.000은 합성 데이터라 패턴이 결정적이어서 나온 값입니다. "정확도 100%"로 내세우지 않고, 의미 있는 지표는 노이즈 테스트와 위의 end-to-end입니다.
